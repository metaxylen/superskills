# Feature specs

**Path pattern:** `docs/superskills/specs/<feature>.md`

Used by `spec-driven-development` and referenced from plans written with `writing-plans`.

## Suggested sections

```markdown
# <Feature>

## Problem
## Goals / non-goals
## User-visible behavior
## Acceptance criteria
## Technical notes (optional)
## Out of scope
```

Keep acceptance criteria testable. Plans break specs into ordered tasks; specs should not duplicate step-by-step implementation unless constraints are global.

## Naming

Kebab-case filename matching the feature slug, e.g. `cursor-symlink-install.md`.
